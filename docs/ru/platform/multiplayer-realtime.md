# Мультиплеер реального времени

Опубликованные приложения получают мультиплеер реального времени, подключая два пакета метахаба: `@universo-react/colyseus-server` (серверный рантайм) и `@universo-react/colyseus-client` (браузерный SDK). Продакшен-комната, которую используют виджеты приложений, - это `FixedTickSceneRoom`, определённый в `packages/universo-react-applications-backend/src/realtime/applicationsRealtimeRuntime.ts`. Сервер владеет состоянием кораблей, назначает один стабильный корабль каждому пользователю, валидирует интенты перемещения и рассылает fixed-tick патчи всем подключённым клиентам.

## Версии зависимостей

| Upstream-библиотека      | Версия  | Потребляется через                |
| ------------------------ | ------- | --------------------------------- |
| `@colyseus/core`         | 0.17.50 | `@universo-react/colyseus-server` |
| `@colyseus/sdk`          | 0.17.43 | `@universo-react/colyseus-client` |
| `@colyseus/schema`       | 4.0.31  | набор зависимостей core           |
| `@colyseus/ws-transport` | 0.17.13 | набор зависимостей core           |

Оба wrapper сохраняют тонкие entry points (`export * from '@colyseus/core'` / `export * from '@colyseus/sdk'`), поэтому обновления upstream остаются внутри workspace-каталога и сборок wrapper.

## Контракт переподключения

Кратковременные обрывы сети не должны дублировать корабли или терять участников. Приведённый ниже контракт реализован в продакшен-комнате; окно переподключения остаётся `RECONNECT_WINDOW_SECONDS = 30`.

-   При несогласованном отключении комната резервирует место контроллера: корабль помечается `connected = false`, а резервация истекает по завершении окна переподключения.
-   Восстановление места проходит через ожидаемый (awaited) вызов `allowReconnection(client, RECONNECT_WINDOW_SECONDS)` внутри сохранённой логики резервации; восстановленный клиент сохраняет свой session id и корабль.
-   Очистка выполняется ровно один раз: `removeClientShip` идемпотентен по дизайну (delete-before-check), поэтому колбэк `onLeave` ядра после неудачной резервации и локальный catch-путь сходятся без дублирующих удалений и «утечек» кораблей.
-   Phantom-seat guard: если обрыв приходится на сессию, у которой маппинг корабля уже удалён, место не резервируется; очистка выполняется немедленно, чтобы комната могла штатно dispose после ухода последнего клиента.
-   Истечение окна завершается по fail-closed: при первой повторной попытке внутри окна `onReconnect` заново проверяет runtime access, и отозванный доступ закрывает зарезервированное место, завершая клиент ровно одним leave-событием.

## Закрепление presence

При attach рантайм создаёт Colyseus `Server` с явным `new LocalPresence()` и отклоняет переменную окружения `COLYSEUS_CLOUD` ошибкой. Благодаря этому presence одиночного процесса остаётся детерминированным вместо зависимости от дефолтов транспорта или облачной конфигурации матчмейкинга.

## Интеграционное покрытие

`packages/universo-react-applications-backend/src/tests/realtime/realServerReconnect.integration.test.ts` поднимает реальный стек Colyseus (core `Server`, WebSocket transport, продакшен-комната) на loopback HTTP-сервере и управляет им реальными SDK-клиентами через пять сценариев:

1. Восстановление места после резкой потери сокета без emit-а leave-события.
2. Продолжение потоковой передачи патчей оставшимся участникам во время переподключения пира.
3. Fail-closed закрытие отозванного места ровно одним leave-событием.
4. Немедленное удаление корабля при согласованном выходе.
5. Штатный dispose комнаты после сброса клиента с уже удалённым маппингом корабля.

Запуск: `pnpm --filter @universo-react/applications-backend test -- realServerReconnect`.
