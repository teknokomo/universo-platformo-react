# Публичные приложения, алиасы и короткие ссылки

Приложение может показывать неавторизованным посетителям опубликованный рантайм только для чтения, например маркетинговую страницу или поддерживаемую матрицу трактовочной сети. Публичный вход разрешается по неизменяемому UUID приложения или по глобальному алиасу:

```text
/a/<uuid-приложения>
/a/<алиас>
```

![Управление слагами приложений](../.gitbook/assets/platform/application-aliases-desktop.png)

UUID остаётся стабильным техническим адресом. Алиас — изменяемое имя маршрута в нижнем регистре длиной не более 63 символов. В алиасах запрещены слеши, percent-escape, управляющие символы, не-ASCII символы, зарезервированные слова маршрутов и значения, похожие на UUID.

## Граница публичного рантайма

Браузер обращается к отдельному публичному endpoint:

```text
GET /api/v1/public/applications/:applicationRef/runtime?locale=en|ru
GET /api/v1/public/applications/:applicationRef/runtime?locale=en|ru&targetKind=page|object&entityTypeId=<uuid-v7>
GET /api/v1/public/applications/:applicationRef/runtime?locale=en|ru&targetKind=page|object&entityTypeCodename=<codename>
```

Запрос отправляется без credentials. Сервер разрешает UUID или алиас, проверяет публичность и публикацию приложения, согласованность установленного рантайма и возвращает allowlist DTO для renderer. Неизвестное, приватное, архивное или неготовое приложение получает одинаковый ответ недоступности, поэтому маршрут не раскрывает состояние приложения. Публичный запрос никогда не выбирает рабочее пространство и не принимает `workspaceId` как разрешение.

Необязательный селектор сущности разрешает активный макет области страницы или объекта в том же готовом публичном приложении. Укажите `targetKind` равным `page` или `object` и передайте ровно один параметр — UUID v7 `entityTypeId` либо `entityTypeCodename`; без селектора используется глобальная область. Селектор не меняет публичность приложения, правила доступа или рабочее пространство.

Для рендеринга `marketing-page` allowlist содержит зарегистрированную позицию шапки (`fixed` или `flow`), чтобы публичная страница совпадала с effective layout Приложения. Старые payload используют `fixed` по умолчанию.

Анонимная навигация сохраняет тот же неинформативный контракт: любой адрес, который не является готовым публичным приложением, ведёт на страницу входа — единообразно для закрытых, неизвестных, архивных, неопубликованных и неготовых адресов. Перенаправление не зависит от конкретной приватной причины, поэтому по нему нельзя определить существование закрытого приложения. Авторизованные администраторы продолжают идти обычным путём членства и guard-проверок.

Защищённая панель управления остаётся на административном маршруте приложения. Публичная ссылка не открывает анонимный CRUD, мутации рантайма, коннекторы, участников, персональное Избранное или неопубликованные настройки. Публичные виджеты используют опубликованные ограниченные контракты чтения.

В трактовочной сети неавторизованный посетитель видит тот же Dashboard и интерфейс Матрицы/рабочего пространства, что и в обычном runtime приложения, но только для чтения. Вместо отдельного публичного интерфейса приложение скрывает элементы авторинга и мутаций. Если доступных публичных рабочих пространств нет, приложение всё равно открывается и показывает локализованное сообщение об отсутствии пространства; перенаправления на вход нет. Анонимный интерфейс не обращается к защищённым API мутаций.

## Управление адресами

Пользователь с разрешением `applicationAliases` может открыть **Администрирование → Экземпляр → Слаги** (адреса приложений). Корневой **Superuser** получает доступ через существующий bypass суперпользователя; новая роль `Superadmin` не создаётся. Это же разрешение назначается существующим ролям и новым пользовательским ролям через обычные правила управления разрешениями.

В редакторе приложения появляется вкладка **Адреса**, если у администратора есть соответствующее разрешение. В ней видны технический UUID-адрес, активные алиасы и политика маршрутизации, а также действия создания, переименования, выбора основного адреса и освобождения алиаса. На центральной странице экземпляра доступны те же операции для всех приложений; при создании используется выбор приложения, а не ручной ввод UUID.

Алиасы глобальны для развёртывания и остаются зарезервированными, пока явно не освобождены, в том числе после архивации приложения. Уникальный индекс базы данных и транзакционная блокировка на приложение защищают создание, переименование, смену основного адреса, освобождение и изменение политики при конкурентных запросах.

Доступны две политики:

| Политика           | Поведение                                                                                                                               |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Прямой доступ      | Каждый активный алиас открывает рантайм приложения.                                                                                     |
| Канонический адрес | Основной алиас является публичным адресом; остальные активные алиасы перенаправляют на него с сохранением суффикса пути и query string. |

Стабильный UUID-адрес работает при обеих политиках. Каноникализация выполняется через same-origin SPA-навигацию с заменой записи истории, поэтому изменяемый алиас не создаёт постоянный внешний redirect.

## Глобальные короткие ссылки `/l`

Глобальная короткая ссылка использует общий для развёртывания слаг и публичный путь `/l/<slug>`. Создавайте ссылки и управляйте ими на странице приложения **Короткие ссылки** по адресу `/a/<applicationId>/admin/short-links`. Слаг приводится к нижнему регистру; допустимы 1–63 символа ASCII — буквы, цифры и дефисы внутри строки. Зарезервированные имена маршрутов платформы отклоняются. Для просмотра, создания и освобождения ссылки требуется роль участника целевого приложения с правом `manageApplication` (`owner` или `admin`) либо существующий обход для корневого **Superuser**. Для списка обязателен `applicationId`, а при освобождении проверяется собственное целевое приложение ссылки.

Публичный маршрут браузера разрешает слаг через `GET /api/v1/public/l/:slug`. Сервер возвращает проверенный объект цели, а не произвольный URL перенаправления; SPA открывает соответствующий маршрут:

| Цель                           | Текущий адрес                                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| Вход в приложение              | `/a/<applicationId>`                                                                                          |
| Раздел Dashboard               | `/a/<applicationId>`                                                                                          |
| Раздел рабочих пространств     | `/a/<applicationId>/workspaces`, только если рабочие пространства включены                                    |
| Опубликованный ресурс рантайма | `/a/<applicationId>?targetKind=page\|object&entityTypeCodename=<codename>` для доступной страницы или объекта |
| Ссылка доступа LMS             | Открывает гостевой рантайм по слагу ссылки доступа этого приложения                                           |

Целевое приложение должно быть публичным и готовым. Цель со ссылкой доступа к тесту должна по-прежнему разрешаться в активный и доступный публичный тест при создании и открытии короткой ссылки. На странице коротких ссылок есть вариант **Ссылка доступа к тесту**. Список доступных вариантов загружается через `GET /api/v1/global-short-links/applications/:applicationId/quiz-access-options?locale=en|ru`. Маршрут требует `manageApplication` для указанного приложения и возвращает только его слаги ссылок и локализованные подписи.

Цель на опубликованный ресурс ограничена страницами и представлениями объектов с поддерживаемым макетом. При создании и открытии ссылки сервер разрешает codename ресурса по актуальным опубликованным метаданным приложения и через публичный resolver эффективного макета. В адресе браузера используется проверенный codename, а не UUID сущности; произвольные URL, имена таблиц, пути и ID записей отклоняются. Прямая ссылка на тест использует отдельную проверенную цель ссылки доступа LMS, которая сохраняет политику гостевого доступа.

Интерфейс коротких ссылок предлагает ссылки доступа к тестам, главную страницу и разделы приложения, а также доступные опубликованные ресурсы с локализованными названиями. Маршрут списка ресурсов — `GET /api/v1/global-short-links/applications/:applicationId/application-resource-options?locale=en|ru`; он требует `manageApplication` в указанном приложении и возвращает только актуальные публичные цели рантайма.

Глобальные маршруты коротких ссылок собираются через `createGlobalShortLinksRoutes()`. Маршруты управления включают `GET /api/v1/global-short-links`, маршруты списков ссылок доступа и ресурсов выше, `POST /api/v1/global-short-links` и `POST /api/v1/global-short-links/:id/release`; каждое действие требует роли `manageApplication` в целевом приложении либо обхода корневого **Superuser**. Освобождение отключает публичное разрешение ссылки и делает слаг доступным для повторного использования. При мягком удалении приложения все его активные глобальные короткие ссылки освобождаются в той же транзакции. Короткая ссылка не открывает административную часть приложения или закрытые данные рантайма.

## Виджет изображения маркетинговой страницы

Макет `marketing-page` размещает центральное изображение типизированным виджетом `marketing.image`, а URL, альтернативный текст, признак декоративного изображения и размеры принадлежат записи объекта `MarketingPageImage`. Шаблон создаёт изображение 1600×900 по умолчанию. Привязка настраивается в редакторе макета, а содержимое — в стандартной форме записи объекта. Первая версия принимает URL ресурса; загрузка, обрезка, обработка и генерация изображений в задачу не входят.

Встроенный шаблон и fixture Консорциума «73-й Меридиан» сохраняют ссылку на демонстрационное изображение MUI в записи объекта `MarketingPageImage`. Чтобы заменить изображение, отредактируйте содержимое этой записи.

## Название и логотип бренда

Виджет `marketing.brand` размещает данные бренда из записи объекта `MarketingPageSiteSettings`. В этой записи хранятся локализованное название бренда и ресурс логотипа; этот же источник содержит общие настройки, которые использует подвал. Привязка управляется в редакторе макета, а контент — через стандартное редактирование записи объекта. Приложение может менять представление и действия, но не дублирует и не переопределяет контент бренда.

## Fixture Консорциума «73-й Меридиан»

Продуктовый snapshot создаётся через существующие Playwright API авторинга и экспорта, а не собирается вручную:

```bash
pnpm run test:e2e:73rd-meridian-fixture-gate:local-supabase
```

Контракт проверяет каждый семантический marketing record в обоих языках, отсутствие демо-тарифов, выдуманных логотипов, придуманных отзывов и неподтверждённых демо-адресов, наличие утверждённых контактов в подвале (Telegram-канал, почта, телефон), а также отключённые действия lead/auth/newsletter. Сгенерированный snapshot записывается в `tools/fixtures/metahubs-73rd-meridian-app-snapshot.json` для импорта в новую тестовую базу. Drift gate сравнивает сгенерированный snapshot с committed fixture после нормализации транспортных ID, hash и timestamp и требует ровно одно вхождение `dashboard.jpg` в hero-ресурсе `marketing.image`. Browser flow импортирует committed fixture, создаёт связанную публичную публикацию и проверяет anonymous runtime по UUID и alias в режимах direct и canonical с сохранением suffix пути и query.

Двуязычные текстовые константы генератора хранятся в репозитории. SHA-256 исходного русского черновика проверяется, если эта необязательная рабочая копия доступна; чистый checkout может создать и проверить fixture без внешнего черновика.
